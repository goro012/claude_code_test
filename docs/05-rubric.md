# 05. 採点ルーブリックと判定ガイド(業務部門向け)

このドキュメントは業務判定者(法務・契約担当)が読むためのものです。プロンプトや Dataverse の知識は不要です。

## 0. Bot の仕組み(判定に必要な範囲だけ)

Bot は2段階で動きます。

1. **段階1**: 対象契約書を読み、問題になりそうな点を「指摘」として列挙します。
2. **段階2**: 各指摘について「法務部チェック済みの雛形契約書にも同じ内容が当てはまるか」を判定します。当てはまる指摘は「当社がすでに受け入れている条件」なので利用者には表示しません。当てはまらない指摘だけを表示します。

皆さんにお願いする判定は、この2段階に対応した **Q1** と **Q2** です。

## 1. お願いしたいこと(3つだけ)

| 依頼 | 頻度 | 所要時間 | 手段 |
|---|---|---|---|
| A. Teams カードで、指摘ごとに **Q1(妥当か)** と **Q2(雛形にも該当するか)** を答える | 評価実行のたび(週1〜3回)、1回あたり最大 20 指摘程度 | 1指摘 1〜2分 | Teams カード(F3) |
| B. 本番フィードバックを「テストケース化 / 見送り / 重複」に振り分ける | 週1回 | 1件 1分 | Teams カード(F4) |
| C. テストケース草案の「期待する指摘」を仕上げる | 採用分のみ | 1件 10〜20分 | モデル駆動アプリまたは Excel |

回答期限は **2営業日** です。期限を過ぎたものは次回に再送されます。
全件を確認する必要はありません。届いたものだけ答えてください。

## 2. カテゴリ(語彙は固定)

| カテゴリ | 含む論点の例 |
|---|---|
| 損害賠償 | 賠償範囲、上限、間接損害の除外、遅延損害金 |
| 契約解除 | 解除事由、催告の要否、中途解約、解約予告期間 |
| 知的財産 | 成果物の権利帰属、著作者人格権、既存知財の扱い |
| 秘密保持 | 秘密情報の定義、例外、期間、返還・破棄 |
| 準拠法・裁判管轄 | 準拠法、専属的合意管轄、仲裁 |
| 支払条件 | 支払期日、検収条件、遅延時の扱い、費用負担 |
| 契約期間・更新 | 期間、自動更新、更新拒絶の通知期限 |
| 反社条項 | 反社会的勢力排除条項の有無、内容 |
| 再委託 | 再委託の可否、承諾要件、責任 |
| その他 | 上記に入らないもの(仕上げ時になるべく上記に振り直す) |

新しいカテゴリが必要になったら校正会で決め、プロンプトと Dataverse の選択肢を同時に更新します。勝手に増やさないでください。

## 3. 重要度

| 重要度 | 定義 | 目安 |
|---|---|---|
| high | 修正しないと契約締結を止めるべき | 無制限の賠償責任、成果物の権利がすべて相手方、反社条項なし |
| medium | 修正を求めるが、相手方が拒否しても締結は可能 | 解約予告期間が短い、再委託に書面承諾が必要 |
| low | 気づいておけばよい。修正要求は任意 | 管轄裁判所が相手方所在地、軽微な文言の不備 |

重要度は「当社の立場(発注側 / 受注側)」で変わります。カードには立場が表示されるので、その立場で判断してください。

## 4. 必須 / 推奨

| 区分 | 意味 | 評価での扱い |
|---|---|---|
| 必須(must) | Bot がこれを指摘しなければレビューとして失格 | 再現率の分母。リリース判定に使う |
| 推奨(should) | 指摘してほしいが、抜けても致命的ではない | 参考指標 |

迷ったら **推奨** にしてください。目安として、契約書1本あたり必須 3〜7 件、推奨 0〜5 件です。

## 5. カードの見方と Q1 / Q2 の答え方(依頼 A)

カードには指摘ごとに次が表示されます。

- 種別バッジ: **一致**(期待していた指摘と対応が取れた)/ **余分**(期待していなかった指摘)/ **欠落**(期待していたのに Bot が出さなかった)
- 対象契約書の条項と **Bot の指摘**(欠落の場合は代わりに「期待していた指摘」)
- **雛形の該当箇所**(Bot が引用した雛形の条項と本文)
- **Bot の段階2判定**(「雛形にも該当する → 表示しない」または「雛形には該当しない → 表示する」)と理由

### Q1: この指摘は妥当ですか?(段階1の評価)

「対象契約書に対する指摘として、法務担当が出すべき内容か」だけを考えます。**雛形のことは考えません。**

| 状況 | 答え |
|---|---|
| 論点も内容も正しい。自分でも指摘する | 妥当 |
| 論点は正しいが重要度や提案がずれている | 妥当 + コメントに「重要度は medium」「提案は○○の方がよい」 |
| 対象契約書にそんな条項はない、読み違えている | 不当 + コメントに「第○条には○○と書かれている」 |
| 論点は存在するが、当社の立場では問題にならない | 不当 + コメントに「受注側では不利にならない」 |
| 対象契約書の全文を見ないと決められない | 判定不能 |

欠落の場合の Q1 は「この期待指摘は今も必要ですか?」と読み替えて、必要 / 不要 / 判定不能 で答えてください。

### Q2: 雛形契約書にも同じ内容が当てはまりますか?(段階2の評価)

「雛形にも同じ状態があるなら、当社はその条件をすでに受け入れているので、指摘を表示しないのが正しい」という考え方です。
Q1 が「不当」でも Q2 には答えてください(段階1と段階2は別々に測ります)。

| 状況 | 答え |
|---|---|
| 雛形にも同じ論点で同じ条件がある(例: 雛形も再委託に書面承諾を要求している) | 該当する |
| 雛形には該当する条項がそもそも無い | 該当しない |
| 雛形に同趣旨の条項はあるが、上限・例外・緩和条項が付いていて指摘の趣旨は解消されている | 該当しない + コメントに「雛形は上限あり」 |
| 雛形の条項は対象契約書より当社に有利で、指摘の趣旨は雛形には当たらない | 該当しない |
| 一部は当てはまるが、指摘の主要部分は雛形には当たらない | 該当しない + コメントに「部分的に該当」 |
| カードに表示された雛形の該当箇所が、実際には別の論点の条文だった(Bot が引用を間違えた) | 実際の雛形を確認して答え、コメントに「引用が誤り」 |
| 雛形の版や立場が対象契約書と合っていない | 判定不能 + コメントに「雛形が違う」 |

**判断の軸は「この指摘を利用者に見せるべきか」です。** 見せるべきなら「該当しない」、見せなくてよいなら「該当する」です。

### 特に見てほしいケース

- **Bot が「雛形にも該当する(表示しない)」と判定したのに、あなたは「該当しない」と思う** … これは利用者から指摘が消えてしまう最も危険な誤りです。理由を必ずコメントに書いてください。
- **余分の指摘で Q1 = 妥当** … 期待指摘に自動で追加されます。Q2 の答えがそのまま「雛形該当(期待)」になるので、Q2 も必ず答えてください。

## 6. 「テストケース化 / 見送り / 重複」の判定ガイド(依頼 B)

| 状況 | 答え |
|---|---|
| Bot が本来指摘すべき論点を落としていた、または誤った指摘をしていた | テストケース化。「本来はこう指摘すべき」を1〜3行で記入し、「雛形にも当てはまるか」を選ぶ |
| 利用者の不満が「雛形と同じ内容なのに指摘された」 | テストケース化。「雛形にも当てはまるか」= 該当 にする(段階2の誤通過の事例になる) |
| 利用者の不満が Bot の性能ではなく使い方・UI に関するもの | 見送り |
| すでに同じ論点のテストケースがある | 重複 |
| 理由が空で判断できない | 見送り(必要なら利用者に直接確認) |

## 7. 期待する指摘の書き方(依頼 C)

Bot の出力を添削する形で書くのが最も速いです。白紙から書かないでください。
立ち上げ期は、Bot の出力に対する Q1/Q2 の回答がそのまま期待指摘になります。

- **1行1論点。** 「損害賠償上限がなく、かつ間接損害の除外もない」は2行に分けます。
- **何を指摘し、何を提案してほしいかを書く。** 例:「受注側である当社の損害賠償責任に上限が無い点を指摘し、対価総額を上限とする修正を提案すること」
- **文言は求めない。** Bot の言い回しが違っても、論点が同じなら一致と判定されます。
- **条項参照を入れる。** 「第12条」「該当条項なし(反社条項が無い)」など。
- **雛形該当を必ず選ぶ。** 該当 / 非該当。分からなければ「未確認」にすると、そのケースは再確認待ちになり集計から外れます。
- **雛形条項参照を入れる。** 該当・非該当のどちらでも、雛形側のどの条項を見て判断したかを書くと、次に見る人が速くなります。
- **根拠は任意。** 書いておくと審査の精度が上がり、新任者の教育資料にもなります。

## 8. 雛形が改版されたとき

雛形の版が上がると、その契約種別の期待指摘の「雛形該当」が変わることがあります。
開発者から「雛形要再確認」のテストケース一覧が届くので、変わった条項に関係する期待指摘だけ「雛形該当」を見直してください。全件見直す必要はありません。

## 9. 校正会(週30分)の進め方

1. 議題一覧を見る: Q1 = 不当、Q1/Q2 = 判定不能、一致した指摘で Q2 と期待値が食い違ったもの、欠落で「不要」とされた期待指摘(5〜10 件)。
2. 1件ずつ、期待指摘を直すか、審査の判断が誤りか、Bot の改善(段階1 / 段階2 のどちらか)が必要かを決める。
3. カテゴリ・重要度・「雛形該当」の解釈が割れた場合は、この文書の該当行を更新する。
4. 決定事項は評価指摘の人コメント欄に追記し、開発者が翌日までに反映する。

議題のないケースは扱いません。「全体の感想」も扱いません。数字は開発者が持ってきます。
